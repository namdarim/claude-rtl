# ‏claude-rtl

متن راست‌به‌چپ در اپ دسکتاپ Claude: پاسخ‌های فارسی، عربی و عبری راست‌به‌چپ نمایش داده می‌شوند، حتی وقتی بندی با یک کلمهٔ انگلیسی، نام فایل یا کد شروع شود.

‏[English](README.md)

## مشکل

اپ دسکتاپ Claude به هر بند، قلم فهرست، سرعنوان و خانهٔ جدول جهت اولین حرفش را می‌دهد. در پاسخ فارسی، بندی که با یک کلمهٔ انگلیسی، نام فایل، `code` یا لینک شروع شود چپ‌به‌راست چیده می‌شود: به لبهٔ چپ می‌چسبد و ترتیب کلمه‌ها و نشانه‌هایش به هم می‌ریزد.

## دو راه حل

| | پلاگین rtl-display | وصلهٔ لینوکس |
| --- | --- | --- |
| سیستم‌عامل | ‏Windows، macOS و Linux | فقط Linux با بستهٔ رسمی `claude-desktop` |
| چه چیزی را درست می‌کند | پاسخ‌های Claude در تب Code | همهٔ متن‌های پنجرهٔ اپ: پاسخ‌های Claude، پیام‌های خودتان، عنوان نشست‌ها، دیالوگ پرسش، فهرست کارها |
| روش | یک پلاگین Claude Code: یک hook ‏`MessageDisplay` هر جا بندی لازم داشته باشد یک علامت نامرئی می‌گذارد | فایل‌های نصب‌شدهٔ اپ را تغییر می‌دهد تا هر صفحهٔ آن یک اسکریپت کوچک بگیرد |
| نصب | دو ورودی در فایل تنظیمات Claude Code یا دو فرمان، بی دسترسی admin | با `sudo`، و دوباره پس از هر آپدیت اپ |
| پشتیبانی | از سیستم پلاگین Claude Code استفاده می‌کند | تغییری غیررسمی در اپ است و Anthropic از آن پشتیبانی نمی‌کند |

پلاگین را به کار ببرید، مگر اینکه روی Linux هستید و می‌خواهید همهٔ بخش‌های اپ درست شود. وصلهٔ لینوکس صفحهٔ خودش را با [شرایط و محدودیت‌هایش](linux-patch/README.fa.md) دارد.

## پلاگین rtl-display

### پیش‌نیازها

- اپ دسکتاپ Claude، تب Code. پلاگین مال Claude Code است، پس به تب Chat نمی‌رسد.
- ‏Python 3. روی Windows آن را از [python.org](https://www.python.org/downloads/) نصب کنید و در نصب‌کننده گزینهٔ «Add python.exe to PATH» را تیک بزنید. `python3` ای که Windows پیش از نصب Python از Microsoft Store پیشنهاد می‌کند خود Python نیست و پلاگین از آن می‌گذرد. اگر اپ Claude هنگام نصب Python باز بود، آن را کامل ببندید، از آیکونش کنار ساعت هم، و دوباره باز کنید تا Python ِ تازه را پیدا کند. macOS و Linux معمولاً Python 3 را از قبل دارند.
- روی Windows، [Git for Windows](https://git-scm.com/downloads/win). ‏Claude Code hookهای پلاگین را با Git Bash ِ آن اجرا می‌کند و پلاگین را با git دانلود می‌کند؛ بی Git for Windows hookها را در PowerShell اجرا می‌کند و این hook آنجا اجرا نمی‌شود.

### نصب از اپ دسکتاپ

1. فایل `settings.json` را در پوشهٔ `.claude` ِ پوشهٔ خانه‌تان با یک ویرایشگر متن باز کنید: روی Windows ‏`%USERPROFILE%\.claude\settings.json` و روی macOS و Linux ‏`~/.claude/settings.json`. اگر نیست، آن را بسازید.
2. این دو کلید را اضافه کنید. اگر فایل از قبل تنظیماتی دارد، آن‌ها را داخل آکولاد بیرونی بگذارید و میان هر کلید و کلید بعدی یک ویرگول بگذارید:

   ```json
   {
     "extraKnownMarketplaces": {
       "claude-rtl": {
         "source": { "source": "github", "repo": "namdarim/claude-rtl" },
         "autoUpdate": true
       }
     },
     "enabledPlugins": {
       "rtl-display@claude-rtl": true
     }
   }
   ```

   می‌توانید همین را در یک نشست Code هم بچسبانید و از Claude بخواهید آن را به همان فایل اضافه کند. اگر با Notepad ِ Windows ذخیره می‌کنید، در «Save as type» گزینهٔ «All files» را بزنید، وگرنه فایل `settings.json.txt` ذخیره می‌شود و کاری نمی‌کند.
3. در تب Code یک نشست تازه باز کنید. Claude Code پلاگین را دانلود و بار می‌کند، و بعد آن را زیر **+** > **Plugins** کنار جعبهٔ پیام می‌بینید.

‏`"autoUpdate": true` می‌گذارد Claude Code پس از هر بار شروع، نسخهٔ تازهٔ پلاگین را خودش بگیرد؛ بی آن، به‌روزرسانی با دست است.

### نصب از ترمینال

جایی که فرمان `claude` کار می‌کند:

```bash
claude plugin marketplace add namdarim/claude-rtl
claude plugin install rtl-display@claude-rtl
```

در یک نشست Claude Code در ترمینال، همین‌ها `/plugin marketplace add namdarim/claude-rtl` و بعد `/plugin install rtl-display@claude-rtl` است. بعد در اپ یک نشست تازه باز کنید.

### به‌روزرسانی و حذف

- به‌روزرسانی با دست: `claude plugin marketplace update claude-rtl`، بعد `claude plugin update rtl-display@claude-rtl`، و بعد یک نشست تازه.
- خاموش کردن یا حذف در اپ: **+** > **Plugins** > **Manage plugins**. اگر آن را از راه `settings.json` اضافه کرده‌اید، دو ورودی‌اش را هم از آنجا پاک کنید.
- یا حذف marketplace و پلاگین با هم: `claude plugin marketplace remove claude-rtl`.

### چه می‌کند

- پیش از آنکه اپ پاسخی را نشان دهد، hook به آغاز هر بند، قلم فهرست، سرعنوان، نقل‌قول یا خانهٔ جدولی که باید راست‌به‌چپ باشد ولی با حرف چپ‌به‌راست شروع می‌شود، نویسهٔ U+200F (RIGHT-TO-LEFT MARK) را اضافه می‌کند. این علامت دیده نمی‌شود، ولی اپ آن را اولین حرف بند می‌شمارد و بند را راست‌به‌چپ می‌چیند.
- در پاسخی که بیشترش راست‌به‌چپ است (دست‌کم یک‌سوم کلمه‌های متنش، بی شمردن کد و لینک)، هر بندی که لازم داشته باشد علامت می‌گیرد، حتی خطی که فقط یک جملهٔ انگلیسی یا نام یک فایل است، تا کل پاسخ از راست چیده شود. در پاسخ انگلیسی فقط بندی علامت می‌گیرد که بیشتر کلمه‌های خودش راست‌به‌چپ باشد، پس جملهٔ انگلیسی‌ای که یک کلمهٔ فارسی را نقل می‌کند جهتش را نگه می‌دارد.
- هیچ علامتی داخل کد نمی‌رود. فهرست، سرعنوان، نقل‌قول، جدول و متن پررنگ یا مورب درست نمایش داده می‌شوند: علامت پس از نشانهٔ فهرست یا سرعنوان، و درست پس از `**` یا `_` آغازین می‌آید.
- فقط نمایش عوض می‌شود. ترنسکریپت، و آنچه Claude می‌خواند، پاسخ را همان‌طور که نوشته شده نگه می‌دارند.
- سد راه نمی‌شود. اگر Python نباشد یا هر خطایی پیش بیاید، پاسخ همان‌طور که نوشته شده نمایش داده می‌شود.
- سریع است: اپ پیش از نمایش هر پاسخ منتظر hook می‌ماند، و روی Linux پاسخی ۵۰۰۰ نویسه‌ای حدود ۰٫۱ ثانیه طول می‌کشد که تقریباً همه‌اش راه افتادن Python است.
- فقط پاسخی را که به آن داده می‌شود می‌خواند و چیزی به جایی نمی‌فرستد.

### محدودیت‌ها

- فقط پاسخ‌های Claude. هیچ hook ای به پیام‌های خودتان، عنوان نشست‌ها، نوار کناری، دیالوگ پرسش و بقیهٔ اپ نمی‌رسد؛ روی Linux وصله این‌ها را درست می‌کند.
- علامت هنگام رسیدن پاسخ اضافه می‌شود. وقتی اپ بعداً نشستی را از ترنسکریپتش بار می‌کند، یعنی پس از راه‌اندازی دوبارهٔ اپ یا باز کردن دوبارهٔ نشست، پاسخ‌های قبلی همان‌طور که نوشته شده‌اند و بی علامت نمایش داده می‌شوند.
- متنی که Claude Code آن را thinking ثبت می‌کند، مثل بخشی از آنچه Claude میان فراخوانی ابزارها می‌نویسد، به hook نمی‌رسد.
- در ترمینال، پاسخی که در چند تکه می‌رسد همان‌طور که نوشته شده نمایش داده می‌شود، چون از یک تکه به‌تنهایی معلوم نیست که داخل بلوک کد شروع شده یا نه. بیشتر ترمینال‌ها هم متن راست‌به‌چپ را خودشان نمی‌چینند.

### اگر چیزی عوض نشد

- پس از نصب یک نشست تازه باز کنید؛ نشست‌هایی که از قبل باز بوده‌اند پلاگین را بار نمی‌کنند.
- مطمئن شوید پلاگین نصب و فعال است: زیر **+** > **Plugins**، یا با `claude plugin list`.
- مطمئن شوید Python همان‌جا که Claude Code hookها را اجرا می‌کند کار می‌کند. روی Windows، ‏Git Bash را باز کنید و `python --version` یا `py -3 --version` را اجرا کنید.
- اگر سازمان شما Claude Code را مدیریت می‌کند، ممکن است فقط hookهایی را که خودش تأیید کرده اجرا کند (`allowManagedHooksOnly`).

### وضعیت

روی Linux آزموده شده است: آزمون‌های آفلاین، و یک نشست واقعی Claude Code 2.1.294 در حالت SDK، همان حالتی که اپ دسکتاپ Claude Code را در آن اجرا می‌کند. در آن نشست hook برای هر پاسخ یک بار اجرا شد و پاسخ با علامت‌ها نمایش داده شد. روی Windows و macOS هنوز امتحان نشده است. اگر آنجا کار نکرد، لطفاً یک issue باز کنید.

### آزمون‌ها

```bash
python3 tests/test_rtl_display.py
```

آزمون‌ها به شبکه و Claude Code نیازی ندارند: قاعده‌های علامت‌گذاری را می‌سنجند و hook را همان‌طور که Claude Code اجرا می‌کند از راه `run.sh` اجرا می‌کنند، از جمله وقتی Python نیست، وقتی stub ِ Microsoft Store جای آن است، و با مسیرهای Windows.
